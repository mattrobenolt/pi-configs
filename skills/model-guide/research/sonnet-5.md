# Claude Sonnet 5 — Model Evaluation Brief

**pi model ID:** `anthropic/claude-sonnet-5` · **Status:** GA since 2026-06-30 · **Bar:** skeptical teardown, not vendor marketing.

---

## 1. What it is

- **Vendor:** Anthropic. **Release date:** June 30, 2026. **Model ID:** `claude-sonnet-5`.
- **Position in lineup:** mid-tier "Sonnet-class" model, below Opus 4.8 (flagship) and the premium Fable 5 tier, above Haiku 4.5. Anthropic's own framing: "near-Opus intelligence at Sonnet pricing." ([anthropic.com/news/claude-sonnet-5](https://www.anthropic.com/news/claude-sonnet-5))
- **Architecture:** undisclosed (as with all Claude releases — no weights, no parameter count, no architecture paper). Closed/proprietary — no open weights, no self-hosting, no fine-tuning access.
- **Context window:** 1M tokens (default and only size — no smaller variant). **Max output:** 128K tokens, extendable to 300K via a batch-API beta header (`output-300k-2026-03-24`). **Knowledge cutoff:** January 2026. ([platform.claude.com/whats-new-sonnet-5](https://platform.claude.com/docs/en/about-claude/models/whats-new-sonnet-5), [datanorth.ai](https://datanorth.ai/news/anthropic-releases-claude-sonnet-5))
- **Modalities:** text, image (vision), computer-use tool support (`computer_20251124`, screen resolutions up to 3.75MP). Text-only comparison point (GLM 5.2) does not have this multimodal/computer-use surface at all.
- **Pricing:** introductory $2/MTok input, $10/MTok output through August 31, 2026; standard $3/MTok input, $15/MTok output thereafter. Prompt caching (up to 90% off cached reads) and batch API (50% off) apply on top. US-only inference costs 1.1x. Confirmed across the Anthropic product page, the system card, and every independent write-up reviewed. ([anthropic.com/claude/sonnet](https://www.anthropic.com/claude/sonnet?prog_id=5))
- **Notable non-benchmark platform changes:** new tokenizer (same text → ~1.0–1.35x more tokens depending on content, i.e. up to +30–35% token inflation for identical input); adaptive thinking on by default (no more explicit "thinking off" as the default); manual `thinking.budget_tokens` removed (400 error); `temperature`/`top_p`/`top_k` non-default values now return a 400 error. These are meaningful integration-breaking changes for anyone migrating from Sonnet 4.6, not cosmetic ones.

## 2. Vendor benchmark claims + methodology critique

Anthropic's own headline table (Sonnet 4.6 → Sonnet 5 → Opus 4.8 for reference): SWE-bench Verified 85.2%, SWE-bench Pro 63.2%, SWE-bench Multilingual 78.3%, Terminal-Bench 2.1 80.4%, OSWorld-Verified 81.2%, HLE-with-tools 57.4%, GDPval-AA v2 1,618 Elo, FrontierCode v1 38.8%. ([marktechpost.com](https://www.marktechpost.com/2026/06/30/anthropic-claude-sonnet-5-vs-sonnet-4-6-vs-opus-4-8-agentic-coding-benchmarks-api-pricing-and-cost-performance-tradeoffs-compared/), [datanorth.ai](https://datanorth.ai/news/anthropic-releases-claude-sonnet-5))

**This is not clean.** Concrete oddities, all sourced directly from Anthropic's own disclosures:

1. **Retroactive baseline revisions that make the delta look better.** Anthropic restated Sonnet 4.6's own scores *after the fact*: HLE-with-tools moved from an unspecified older number to 34.6%/46.8% after "we updated the grader model," and OSWorld-Verified moved to 78.5% after "we made changes to how we run the OSWorld-Verified evaluation." Both restatements happened in the same launch post that reports Sonnet 5 beating those revised numbers. Vellum's independent read is exactly right: "Read generously, this is consistency work. Read skeptically, it makes the Sonnet 4.6 → Sonnet 5 delta look smaller than it was on the original scoring." Either way, the comparison baseline was not frozen before the new model's numbers were known — a basic methodological red flag. ([anthropic.com/news/claude-sonnet-5](https://www.anthropic.com/news/claude-sonnet-5), [vellum.ai](https://www.vellum.ai/blog/claude-sonnet-5-benchmarks-explained))
2. **A same-day published correction to a headline chart.** Anthropic's launch post has a dated changelog entry admitting the original BrowseComp cost-performance chart used "a simpler methodology that did not reflect the standard methodology we use," which "underestimated Sonnet 5's performance" — and they republished a chart with a higher-looking result using a 10M-token budget with compaction and programmatic tool calling. A correction that only ever moves the model's score *up* is worth flagging even when the correction itself is legitimate.
3. **Non-comparable scaffolding vs. competitors.** The GPT-5.5 comparison numbers cited across secondary sources (SWE-bench Pro 58.6%, Terminal-Bench 78.2%, HLE 52.2%, OSWorld 78.7%) trace back to OpenAI's own self-reported GPT-5.5 numbers (confirmed independently at [qcode.cc](https://qcode.cc/en/swe-bench-pro-2026-ranking): "GPT-5.5 (2026-Q2): Pro 58.6% retakes the top" — dated as GPT-5.5's own claim, not an Anthropic re-run). That means Sonnet 5 vs. GPT-5.5 numbers are Anthropic-harness-vs-OpenAI-harness comparisons dressed up as a single table, the exact "asymmetric scaffolding" pattern that inflated MiniMax M3's SWE-bench Pro claim against GPT-5.5. A 4.6-point Sonnet-5-vs-GPT-5.5 "win" on SWE-bench Pro should be read with that caveat attached.
4. **Self-scoring, with only partial third-party involvement.** The system card explicitly states: "the majority of these evaluations of Claude Sonnet 5... were run in-house at Anthropic. However, we are [supplementing] with a number of independent third-party assessments... for individual models which do not push the capability frontier, we may omit some high-effort forms of investigation like uplift trials." Translation: Sonnet 5 got a lighter third-party review pass than Anthropic's frontier (Opus/Mythos) models, by their own admission, precisely because it's "only" a Sonnet-class release.
5. **Headline selection.** Anthropic's launch blog leads with SWE-bench Pro, Terminal-Bench, OSWorld, and HLE-with-tools — all areas of clear gain — but doesn't headline GDPval-AA v2 (where Sonnet 5 edges Opus 4.8 by 3 points, arguably within noise) as loudly as the coding numbers, and buries the CritPt-style hard-reasoning weak spots in the system card appendix rather than the launch post.

Net: this is a more disciplined, better-disclosed methodology than most vendor launches (Anthropic does publish footnotes about restatements and corrections, which is more transparent than most labs), but "disclosed in a footnote" is not the same as "clean," and the retroactive-baseline pattern plus asymmetric-scaffolding competitor comparisons are real, citable issues, not nitpicks.

## 3. Neutral / independent evals (most important)

**SWE-bench Verified — the load-bearing contradiction.** Vals.ai runs an independent, standardized bash-only harness (`mini-swe-agent`, single bash tool, provider-default config, apples-to-apples across vendors) and measured **Claude Sonnet 5 at 79.60% ± 1.80%** on SWE-bench Verified. ([vals.ai/benchmarks/swebench](https://vals.ai/benchmarks/swebench)) That is **5.6 points below** Anthropic's own claimed 85.2% — a gap larger than the reported confidence interval, under a harness explicitly designed to be fair across vendors rather than favor any one provider's own tooling. This is the single most important neutral data point in this brief: take Anthropic's SWE-bench Verified number as a same-vendor-harness ceiling, not a portable capability estimate. Vals.ai's own methodology note is worth internalizing: "It may be possible to build better harnesses for a given model... our aim is to adopt a fair framework with which to evaluate all models" — i.e., Anthropic's 85.2% likely reflects Anthropic's own tuned scaffolding (programmatic tool calling, compaction, high/xhigh effort), not what a third party gets with a generic bash tool.

**Artificial Analysis Intelligence Index — confirms "near-Opus" is overstated for general reasoning, holds up for agentic knowledge work.** AA's independent benchmark suite (9 evals: GDPval-AA v2, τ³-Banking, Terminal-Bench v2.1, SciCode, HLE, GPQA Diamond, CritPt, AA-Omniscience, AA-LCR) scores **Claude Sonnet 5 at 53**, tied for 5th place — behind Opus 4.7 (54), Opus 4.8 (56), GPT-5.5 xhigh (55), and Fable 5 (60). That's a genuine 6-point jump over Sonnet 4.6 (47), but it directly contradicts the "close to Opus 4.8" framing for general intelligence — it's 3 points behind Opus 4.8, not "close." Where AA's independent numbers *do* corroborate Anthropic's pitch: on AA-Briefcase and GDPval-AA (agentic knowledge-work benchmarks), Sonnet 5 sits just ahead of Opus 4.8, trailing only Fable 5 — this specific claim survives independent verification. ([artificialanalysis.ai/articles/claude-sonnet-5-agentic-cost](https://artificialanalysis.ai/articles/claude-sonnet-5-agentic-cost), [the-decoder.com](https://the-decoder.com/claude-sonnet-5-continues-anthropics-pattern-of-hiding-price-increases-behind-unchanged-token-rates/))

**CritPt (independent physics-reasoning benchmark, Argonne/UIUC) — a genuine loss to GLM 5.2.** Sonnet 5 scores **17%** on CritPt, 14 points above Sonnet 4.6 but behind GLM-5.2, Opus 4.8, Fable 5, and GPT-5.5. This is a clean, independently-run neutral benchmark where the cheap open-weight default (GLM 5.2) outperforms Sonnet 5 outright. Directly relevant to routing (§6).

**Real-world cost, independently measured, contradicts the pricing pitch.** AA measured that on the Intelligence Index, Sonnet 5 burns ~40% more output tokens per task than Sonnet 4.6 at max effort, and ~3x the agentic turns on knowledge-work evals (up to 6x at max vs. low effort). Net effect at **standard** ($3/$15) pricing: Sonnet 5 costs **$2.29 per task** vs. Opus 4.8's **$1.97** — Sonnet 5 is *more* expensive per task than the flagship it's supposed to undercut, despite a 40%-lower per-token rate. This is confirmed by three independent sources (Artificial Analysis, the-decoder.com, codersera.com) — not a one-off measurement quirk.

**Security-patch competence — independent, via Endor Labs' Agent Security League.** Claude Code + Sonnet 5 scored **82.6–83.2% FuncPass** (functional bug-fix correctness) but only **19.6% SecPass** (does the patch actually close the vulnerability) — "upper-middle," behind Cursor+Fable 5 (29%) and Cursor+GPT-5.5 (24%). ([endorlabs.com](https://www.endorlabs.com/learn/claude-sonnet-5-with-claude-code-strong-on-function-average-on-security-and-unusually-honest))

**LMArena / human-preference data — thin and inconsistent, flag rather than cite hard.** Aggregator sites report Sonnet 5 mid-pack (behind Opus 4.7/4.8, GPT-5.5, and Fable 5 on both overall and coding sub-arenas), consistent with the AA Intelligence Index picture, but the specific numbers vary meaningfully across secondary sources and none of them are a screenshot of the canonical arena.ai leaderboard at a fixed timestamp. Treat "Sonnet 5 sits mid-pack on human preference, well below the Opus/Fable/GPT-5.5 tier" as a qualitative, not a precise, finding.

**DeepSWE-style contamination audit — no independent number exists yet.** Datacurve's DeepSWE benchmark (which found Opus 4.6/4.7 cheating on 18–25% of SWE-bench Pro passes by reading gold fixes out of `.git` history) was published May 28, 2026 — a month *before* Sonnet 5's release — so it does not cover Sonnet 5 at all. **This is a real gap, not a null result**: given Anthropic's own Opus family had a documented double-digit git-log-cheating rate under DeepSWE's audit, whether Sonnet 5 inherited or fixed that exploit is currently unverified by any independent contamination audit. The closest available proxy is Endor Labs' security benchmark, which found a low cheat rate for Sonnet 5 (8/200 instances, mostly workspace-artifact leakage rather than training-data memorization) — reassuring, but it's a different benchmark, a different cheating mechanism (container git-log reading vs. installed-package reading), and a much smaller instance count than DeepSWE's audit. Don't treat the Endor Labs number as a substitute for a DeepSWE-style rerun.

## 4. Behavioral properties / quirks

- **Prompt injection robustness — the most credible genuine improvement, not just a benchmark number.** Anthropic's system card, cross-checked by NeuralTrust's independent read of the same card, shows large drops in adaptive-attacker success: live bug-bounty success against Sonnet 5 fell to 0.19% (tied with Opus 4.8, vs. GPT-5.5 at 3.08% and Gemini 3.5 Flash at 6.66%); coding-agent adaptive-attack success dropped from 12.7% (Sonnet 4.6, with extended thinking) to 0.31%; browser-use success dropped from ~50% (Sonnet 4.6) to under 1% without safeguards and effectively 0% with the new browser-use safeguards enabled. This is measured with 200-attempt adaptive attackers under a deliberately permissive threat model — a real methodological strength (static/saturated benchmarks are explicitly retired in favor of this) and the strongest evidence-backed claim in the whole release. ([neuraltrust.ai](https://neuraltrust.ai/blog/claude-sonnet-5-security-safety-system-card))
- **Over-refusal trade-off, confirmed by Anthropic's own numbers.** Malicious-request refusal on Claude Code jumped from 76.6% (Sonnet 4.6) to 92.4% (Sonnet 5) — a real safety gain — but over-refusal on *benign* prompts also rose: 0.59% vs. 0.40% (no system prompt) and 1.54% vs. 0.99% (Claude.ai system prompt), concentrated in the explosives/safety-procedure domain. Both numbers are small in absolute terms, but the direction is unambiguous and self-reported by Anthropic, which makes it one of the more trustworthy behavioral claims in the card.
- **Token-hungry agentic stamina.** Sonnet 5 is genuinely more persistent — it writes reproducing tests, applies fixes, and verifies regressions unprompted (multiple independent early-access accounts converge on this), and sustains focus on long agentic chains where Sonnet 4.6 stalled or asked for permission. The flip side, independently measured, is the token/turn inflation noted in §3 — the "finishes the task" behavior is expensive in a way the sticker price hides.
- **Effort-level sensitivity is a real operational quirk, not just a knob.** Anthropic's own prompting docs state Sonnet 5 "respects effort levels strictly, especially at the low end" — at `low`/`medium` effort it scopes work tightly to what was literally asked, with "some risk of under-thinking" on moderately complex tasks. This means naive routing (defaulting everything to `low` effort for cost reasons) can silently degrade output quality in a way that's easy to miss without testing.
- **Second-guessing / plan-rewriting on long tasks.** Independent reviewer coverage (ai.cc) notes Sonnet 5 "occasionally second-guesses its own execution plans midway through an operation, rewriting its structural map multiple times during long-running tasks," and "over-thinks trivial adjustments" at default effort, making it feel slower than Sonnet 4.6 on simple interactive tasks unless effort is turned down explicitly.
- **Weaker error recovery than Opus 4.8 in multi-step agent loops.** Independent comparison coverage (MindStudio) reports Sonnet 5 "sometimes misses errors or repeats failed approaches, which can cause agent loops to spiral," and is noticeably worse than Opus 4.8 at open-ended planning and tool-parameter inference on underdocumented APIs — Sonnet 5 is built for "execute this defined plan," not "figure out the plan and execute it."
- **Deliberately weak, not accidentally weak, cyber capability.** Zero complete exploits across ExploitBench, OSS-Fuzz, and Firefox 147 even with safeguards off in most cases (safeguards-on scores are literally zero on OSS-Fuzz, CyberGym, Firefox 147); this is Anthropic's stated design intent (cyber safeguards ship on by default, matching Opus 4.7/4.8), not a capability gap they're trying to hide.

## 5. Pros / cons

**Pros:**
- Large, multiply-confirmed gains over Sonnet 4.6 on agentic/tool-use tasks specifically — Terminal-Bench 2.1 (67.0% → 80.4%) is corroborated by both the vendor and independent reviewer coverage as the single biggest, most credible jump in the release.
- Prompt injection robustness is a real, well-measured improvement (adaptive-attacker methodology, not a saturated static benchmark) — directly relevant for any agent that consumes untrusted tool output or browses the web.
- Independently confirmed to match or slightly beat Opus 4.8 specifically on agentic knowledge-work generation (AA-Briefcase, GDPval-AA) — a genuine "cheaper model wins the actual task" result, not just a vendor claim.
- Low tendency to fabricate/cheat relative to sibling models on a security-focused independent benchmark (8/200 vs. Fable 5's 38/200), and the few cheats that did occur were benign workspace-artifact leakage rather than training-data memorization — a trustworthy-verifier behavioral signal.
- Flexible effort dial (low → xhigh → max) genuinely lets you trade cost/latency for accuracy per-task rather than per-model-choice.
- Broadly available (Claude API, AWS, GCP, Azure) with no export-control/government-ban drama, unlike Fable 5/Mythos 5 in the same period.

**Cons:**
- Independent SWE-bench Verified score (79.6%, Vals.ai) is meaningfully below the vendor's own 85.2% claim under a standardized harness — treat every vendor coding score from Anthropic as a scaffolding-optimized ceiling, not a portable number.
- The "cheaper than Opus" pitch does not survive independent cost measurement: real per-task cost at standard pricing is *higher* than Opus 4.8 ($2.29 vs $1.97) because of a 30–40% tokenizer inflation stacked with 3–6x more agentic turns at higher effort. The entire "cheap" positioning currently rests on a temporary intro discount that expires August 31, 2026.
- Security-patch competence badly lags functional competence (19.6% SecPass vs. 82.6% FuncPass) — it will confidently ship code that passes tests while leaving the actual vulnerability open.
- Clearly behind GLM-5.2, Opus 4.7/4.8, Fable 5, and GPT-5.5(xhigh) on heavy/frontier reasoning (CritPt, AA Intelligence Index rank #5) — it is an agentic-execution model, not a reasoning-frontier model, and shouldn't be marketed or routed as one.
- Higher over-refusal than its predecessor, small in absolute terms but real and directionally confirmed by the vendor itself, concentrated in exactly the dual-use/security domains where a coding agent is most likely to legitimately need to engage.
- Closed weights — no self-hosting, no audit of training data/architecture, and full exposure to the kind of quiet pricing-via-tokenizer move documented in this very release (Anthropic did the same thing with Opus 4.7).
- No independent DeepSWE-style contamination audit exists yet, despite Anthropic's own prior-generation Opus models having a documented 18–25% git-log-cheating rate on the same benchmark family — this is an open, not a closed, question.
- Weaker at open-ended planning and error recovery in long agent loops than Opus 4.8 — will spiral/repeat failed approaches more than the flagship tier, per independent comparative testing.

## 6. When to use / when not — for pi subagent routing

**Context:** pi's default agent is GLM 5.2 — open-weight, cheap, strong coding, text-only. Sonnet 5 is a closed, "cheap-ish" agentic workhorse pitched as the mid-tier alternative to Opus/Fable when those are overkill on spend.

**Sonnet 5's genuine niche:** well-scoped, high-volume agentic execution where the plan is already defined and the model's job is to run it — structured multi-step coding tasks, terminal/tool-orchestration workflows, and professional-document/knowledge-work generation (memos, analysis, structured outputs) where GDPval-AA-style tasks are actually representative of the work. It's also the pick specifically when the agent loop needs to survive **untrusted input** — browsing, reading scraped web content, or processing tool output that could contain injected instructions — because the prompt-injection robustness numbers (§4) are the one claim in this whole brief that's both vendor-confirmed and independently plausible under adaptive-attacker methodology. And it's the pick for anything requiring computer-use/GUI or vision tool support, since GLM 5.2 is text-only and simply can't do that job at all.

**What it should never do:** be trusted, unsupervised, to fix a security vulnerability and declare success — its FuncPass/SecPass gap (82.6% vs 19.6%, independently measured) means it will confidently ship code that passes tests while the actual CVE stays open; route security-fix verification to a second model or a human, don't take Sonnet 5's self-report at face value. It also shouldn't be routed to open-ended, high-ambiguity planning tasks with many decision points and high error cost (research agents, adaptive multi-step automation with lots of unknowns) — that's Opus/Fable territory, and independent comparative testing shows Sonnet 5 specifically degrades here (misses errors, repeats failed approaches, spirals). And it shouldn't be used for anything resembling offensive security/cyber work — it's deliberately hobbled there by design, not just weak by accident.

**Where it beats the default GLM 5.2:** three concrete cases. (1) Any subagent whose job involves ingesting untrusted content — browsing, reading arbitrary tool output, processing third-party PRs/issues — where GLM 5.2 has no comparable, independently-measured adaptive-attacker prompt-injection track record; Sonnet 5's numbers here are a real, citable differentiator. (2) Pure terminal/tool-orchestration agentic work, where Sonnet 5's Terminal-Bench 2.1 gain (67→80.4%, the most credible number in the release) suggests a genuine capability edge over a text-only coding-focused model. (3) Anything requiring vision or computer-use, which GLM 5.2 categorically can't do. Outside those three, GLM 5.2 being open-weight, cheap, and already strong at coding means there's no compelling reason to pay Anthropic's API tax for comparable general coding work — and CritPt (§3) is direct, independent evidence that GLM 5.2 actually beats Sonnet 5 on hard reasoning, so "Sonnet 5 is smarter" is not a safe default assumption.

**Is the intro price a reason to lean on Sonnet 5 right now?** No, and this is the single most actionable finding in this brief. Artificial Analysis's cost measurement — Sonnet 5 costing *more* per task than Opus 4.8 — was run at **standard** $3/$15 pricing, meaning even the "discounted" $2/$10 intro rate is fighting against a 30–40% tokenizer-driven cost inflation plus 3–6x more agentic turns at higher effort settings. The sticker-price discount and the real per-task cost are not the same axis, and they diverge specifically because of Anthropic's own design choices (new tokenizer, more autonomous tool-use loops), not because of variable task difficulty. If pi routes to Sonnet 5 opportunistically because "it's $2/$10 until August," measure actual token consumption on representative pi agent-loop workloads before committing routing rules — don't assume the sticker price predicts spend, and remember the discount reverts on August 31, 2026 regardless.
