# Model Guide

A living evaluation doc for picking which model a subagent should run on — and a light policy layer that shapes agent model selection over time. It accumulates findings rather than getting rewritten each pass.

Specs are from `pi --list-models` (operational truth for this setup, not vendor headlines). Prices are USD per 1M tokens, list price; the Fireworks-hosted rows reflect the configured `fireworks` provider. **AA Index** is the Artificial Analysis Intelligence Index (independent composite, ~0-100) — the one neutral number available across the field. Context-window caps are intentional, not deficiencies (see the note at the bottom).

## How to maintain this doc

- **Findings logs are append-only.** Each model has a dated `Findings log` that accumulates evidence. Never edit a past finding in place — append a new dated entry that supersedes it if the picture changes, and update the stable blocks above to reflect the current synthesis. **Exception (Matt, 2026-09-29): periodic culls compress dead history** — entries about retired models, resolved watch items, and superseded comparisons get folded into one line with a pointer to `research/<slug>.md`, which is the archive. The log is for decision-relevant history, not a transcript.
- **Stable blocks evolve.** `What it is`, `Vendor claims & methodology`, `Neutral evals`, `Behavioral properties`, `Pros`, `Cons`, `When to use`, `When not to use` are the current synthesis — rewrite them as understanding improves. The Findings log is the audit trail.
- **Skepticism is the default.** Vendor claims go in `Vendor claims & methodology` with the methodology critiqued. `Neutral evals` is the field that matters most — hunt for the independent number that confirms, qualifies, or contradicts the vendor headline. Every model in this guide had a vendor headline that partially failed a neutral cross-check; assume the same of future models.
- **Source briefs live in `research/<slug>.md`** (next to this file in the skill dir). Log a top-level Changelog entry when a model's synthesis materially changes. Changelog keeps ~the current month; older history is `git log` + the briefs.

## Selection protocol

**Default to DeepSeek V4.1 Flash at `max` thinking** (`fireworks/accounts/fireworks/models/deepseek-v4p1-flash`) — Matt, 2026-09-16. Parity with its predecessor on every local arm, vision added, needles clean to ~925K. Accepted costs: durable verbosity (~1.5-2x predecessor spend per accepted text task; AA 250M output tokens vs 130M median), no `off`/`minimal` gear, in-loop cache 50% vs family 78-87%. Bans: never a verifier (1/5 fabrication); budget output caps on extraction calls (reasoning hunger length-truncates). **Escalation past the default is cross-family: GLM 5.3 for one-shot-expensive text (K3-cluster DeepSWE at ~1/3 K3's token price) or K3 for repo-scale + vision.** **One live default-seat challenger: GLM 5.3 Flash** (cheaper per token, parity + vision + working ~925K, ban-probes clean at n=10) — swap pending Matt's call. GLM 5.3 owns the GLM seat outright; deep context past ~200K routes to the DeepSeek default (5.3-proper's ~925K serving defect is unre-probed).

**Open-weight bias for day-to-day; closed when it makes sense.** Day-to-day leans DeepSeek / GLM / Kimi / MiniMax. Pull closed (Claude, GPT) in for quorums or when their specific strength is the point. Don't default to closed just because it's frontier — under neutral harnesses the closed-model coding leads shrink or reverse.

**Kimi K3 is additive: paired frontier executor + hard-task escalation.** It does not replace GLM 5.3, Opus 5.5, the Sol seat, or Fable. Use it for difficult repo-scale coding and vision when its frontier-cluster DeepSWE result justifies the premium. Preferred hard-work pattern: **Opus 5.5 plans/reviews → K3 implements → mechanical checks or the parent accept** (a routing recommendation, not a measured collaboration result). Never let K3 define and accept its own success criteria — its explicit imaginary-grader/eval-maxxing failure mode makes that unsafe. Throughput is provider-split (Fireworks ~163 tok/s, first-party crawled at ~33); it acts on ambiguity (specs need explicit non-goals) and its failure shape is an expensive confident loop (bound runs with turn/token budgets). GLM 5.3's neutral DeepSWE (69.0 ±2.7) matches K3's cluster at ~1/3 the token price for text — K3's durable edges are vision and the pairing pattern; the text-escalation split is Matt's open call. **Ember-1 (Fireworks' K3 token-efficiency fine-tune, research preview) is the live challenge to K3's economics**: same sticker, claimed K3-max quality at ~60% per-task cost — all numbers Fireworks-run, K3's bans carry, and the two-week serverless clock (~2026-10-07) bars durable routing. ## Thinking levels

pi exposes seven thinking levels: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`. Set globally in `settings.json` (`defaultThinkingLevel`), per-agent via `thinking:` frontmatter, or per-invocation via `--thinking`. Higher levels trade tokens/latency/cost for reasoning depth; per-model support varies (holes are allowed).

- **GPT-5.6 Sol / Luna** — full `none`→`max` ladder native. Sol's `max` pairs with `ultra` (cooperating subagents, Sol-only, ~2-4x cost).
- **GPT-6.1 Sol** — `low`→`max`, **no `off`** (`off`→null, `minimal`→`low` in models-store.json — GPT-6 Sol's `none` gear is gone). Gateway default assumed `low` (family pattern; unverified on 6.1) — pin it. Vendor DeepSWE peaked at `high` (75.2) and *dropped* at `xhigh`/`max` (71.9) — the top rungs bought nothing on the headline row.
- **GPT-6 Astra** — `low`→`max`. **Gateway default is `low`** — an unpinned call runs the flagship under-powered. `max` is where its Coding Agent Index lead was measured. Thinking cannot be disabled.
- **Claude Opus 5.5 / Sonnet 5.5** — adaptive thinking, no thinking-off at all (`off`/`minimal` unmapped; Sonnet 5.5's floor is `between_tools` at `high`-or-below). Five levels `low`→`max`. **Opus 5.5 defaults `medium`; Sonnet 5.5 defaults `high` on the API, `medium` in Claude Code** — pin effort. Both inverted at `max` on launch curves (Opus TB4: max 64.8 < xhigh 66.4; Sonnet FrontierCode: max 46.2 < xhigh 52.1). Sonnet 5.5's `max` is the AA-measured token furnace (193K out/task) — independent hands-on: `medium` matched `high` on routine generation at half the tokens, `max` cost 20-22x `medium` for identical scores, `low` failed to deploy. **`medium` is the routine gear; `high`/`xhigh` for long agentic tasks (the CursorBench effort curve is real); `max` only where an eval proves it pays.**
- **Claude Opus 5 / Sonnet 5 / Fable 5.1** — adaptive; `max` native. Fable 5.1: five explicit levels, default `high` — a real cost/latency lever (~6.2s first token at `low` vs 131s at `max`; low-effort 5.1 ≈ Fable-5-max quality at ~¼ price, vendor curve). Sonnet 5/Opus 5: adaptive on by default, budget can't be removed.
- **DeepSeek V4.1 Flash (the default)** — `low`→`max` on Fireworks, no `off`/`minimal` (probed live 2026-09-10); thinking effectively required. Run `max` per family practice. Schema + thinking is safe (10/10 probe).
- **GLM 5.3** — thinking **cannot be disabled** (`none` rejected, no `minimal`; native ladder `low`→`max`, defaults `max`). `low` measured 6/6 on the routine coding pack — a legitimate cheap gear. Deep-context caveat: ~925K requests currently never return on the Fireworks route.
- **Kimi K3** — always thinks; `low`/`high`/`max` (default `max`). Requires the complete prior assistant message — including `reasoning_content` and `tool_calls` — on every subsequent turn. Do not hot-swap into K3 mid-session or use a harness/compactor that strips preserved thinking.
- **Ember-1** — full Fireworks enum incl. **`none`, verified to disable reasoning** — a gear K3 proper lacks. **The unpinned default is heavy** (4,014 reasoning tokens into a 4,096 cap, `finish: length`; the K3 truncation shape). The lean behavior lives at `low`/`high` (15-19 reasoning tokens, 76-82 tok/s). Pin the level on every call — down, not up.
- **Qwen3.8-Max** — full ladder on Fireworks (`off`→`none` verified disabling). Native levels low/medium/xhigh and **the default is xhigh** — set the level explicitly on cheap work.
- **MiniMax M3** — three modes; pi limits the ladder to `low`/`medium`/`high`.
- **Grok 4.6** (no seat — reference only) — `low`/`medium`/`high`/`xhigh`; reasoning cannot be disabled; default `high` is the worst measured point on the raw-API curve (VulcanBench, non-monotone) — if it ever runs, pin `medium` (routine) or `xhigh` (hard, budgeted).
- **nemotron-lightning-3p5-30b-a3b** (utility: scout, webfetch objectiveModel) — NVIDIA 30B MoE, $0.05/$0.20 on Fireworks; a reasoning trace precedes every answer — keep effort low for the cheap recon tasks it's routed to.

Routing rule of thumb: match thinking level to stakes, not to model. Low-stakes utility work (scout, objectiveModel, deslop) stays `low`/`medium`; hard coding and review escalate to `xhigh`/`max` on the models where the top rungs measured a gain. Don't pin `max` globally — on three 2026-09 launches (Opus 5.5, Sonnet 5.5, 6.1 Sol) the top rung measured flat-to-inverted on the vendors' own curves.

## Cyber safeguards & prompt framing — GPT-6.x, GPT-5.6, Fable 5.1, Opus 5.5, Sonnet 5.5 *(and families)*

The current frontier models all ship safety layers that block *offensive* cyber work — and all over-trigger on legitimate defensive work, because the classifiers read surface keywords, not intent. "Review my own code for security issues before I ship" is lexically near-identical to "find vulnerabilities in this code," so the defensive case gets caught. Documented, not anecdotal:

- **GPT-6.1 Sol** — **Critical cybersecurity threshold** (Preparedness Framework), same safeguards stack as Astra. ExploitBench 99.7% @max, ExploitGym 35.1% (vs Astra 42.4) — measured safeguards-off; the API default serves safeguards-on, advanced access gated behind Trusted Access/Daybreak. The Sol-family situation carries: red-team-shaped work needs the cyber-allowed path.
- **GPT-6 Astra** — the first OpenAI model at the **Critical** threshold. Headline exploit numbers (ExploitBench 100%, SRE-Bench 88% — two previously-unknown zero-days found during eval) were measured **without production safeguards**; the API default serves safeguards-on. ZDR available for eligible API customers.
- **GPT-5.6 Sol** — OpenAI's own deployment hub: safeguards "block roughly ten times more potentially harmful activity" than 5.5 and "can create friction for benign users," with a built-in "retry on lower-capability models" escape hatch. Per reporter analysis a secondary "guardian" model pattern-matches for offensive security and can't read intent — and Sol's output is good enough that high-quality security help looks "too good to be benign" to the dumber guardian (the competence paradox). All 5.6 tiers carry the "High" cyber designation + the API `cyber_policy` error path. Field note (2026-08-09): Codex refused 4/4 authorized hunt tasks until the account was swapped to a Cyber-allowed subscription — then completed them cleanly.
- **Sonnet 5.5 (2026-09-28) — the first Sonnet with flagship-class cyber safeguards.** System card, plain terms: "users should expect increased refusals with Sonnet 5.5, even on benign cybersecurity-related tasks." Blocked requests fall back to **Sonnet 5** (automatic in Anthropic's apps; opt-in on the API). Route known cyber work directly at its target instead of dancing with the classifier.
- **Opus 5.5** — first Opus with Fable-class safeguards: cyber reroutes to Opus 4.8 (still retired — route known cyber work to Opus 5 directly), bio reroutes to Opus 5. Preserved thinking binds API accounts created ≥2026-08-31 (no editing prior assistant context). Launch benchmarks ran safeguards-on with disclosed fallback completions (deflates scores, per Anthropic).
- **Fable 5.1** — classifiers over cyber / bio / distillation, materially more precise than Fable 5's (~60% fewer cyber false positives; defensive source-code vuln discovery now allowed on-model; exploit-gen/pentest still redirect). Fallbacks unchanged: cyber → retired Opus 4.8, bio → Opus 5. Anthropic concedes benign cyber work may trip the safeguards; apps/Claude Code silently reroute, the API returns `stop_reason: "refusal"` with no auto-fallback. Family blast-radius record: one operator logged ~80% of a defensive-CTI session served by the fallback; 20.9% fallback on Terminal-Bench vs <5% marketed; once flagged, a session stays rerouted. The 2026-08-09 exosphere confirmation (4/4 framing-immune cyber blocks incl. authorized-preamble retries) was measured on Fable 5 — assume it carries until probed on 5.1. High-risk dual use is policy-gated, not prompt-tunable.

**Frame prompts to avoid the trip entirely.** The classifiers are surface-pattern matchers; the cheapest block is the one that never fires. For security review of your own code (the whitehat/defensive case — reviewing your own implementations or security fixes before shipping), write the request as an authorized defensive work order, not an attack:

1. **Lead with authorization + scope + goal + output boundary.** State the code is yours and you're reviewing pre-ship; instruct the model to analyze only the files/snippets you provide (no external scanning); say the output should be remediation-shaped.
2. **Swap offensive vocabulary for defensive vocabulary** — the classifier can't tell intent apart, so remove the lexical noise:

   | Trips the classifier | Defensive rephrase |
   | --- | --- |
   | "find vulnerabilities in this code" | "review this code for correctness/robustness issues" |
   | "exploit this bug" | "reproduce this bug in a test case" |
   | "bypass the check" | "refactor the check" |
   | "attack surface / injection points" | "input boundaries / untrusted-data paths" |
   | "how would I break this" (whitehat lens) | "what failure modes could this hit in production" |
   | "hook into the login flow" | "add middleware to the login flow" |

3. **Ask for remediation, not offense.** Request risk/impact explanation, patch draft, tests to add, human review points. Do **not** request exploit payloads, evasion, C2, lateral movement, persistence, or exfiltration — that cluster is what the guardian is keyed on.
4. **Split discovery from validation.** Don't combine "find + reproduce + automate" in one prompt — that triple looks offensive even when benign. Get impact + remediation direction first; ask for the test/patch separately.
5. **On the Claude models, drop "show your reasoning in the reply" instructions.** Echo/transcribe-reasoning prompts trip a separate `reasoning_extraction` refusal category; use structured `thinking` blocks for visibility instead.
6. **Keep system prompts short and non-contradictory.** Overloaded (>~800-1000 token) or self-contradictory system prompts raise false-positive rates — the classifier reads the contradiction as suspicious.
7. **If a session gets flagged, start clean.** The trigger phrase stays in context and re-trips next turn; `/model` back doesn't help. Don't argue with the classifier or ask it how to bypass itself — that's a separate jailbreak concern, not a prompt-framing fix.

**When the work genuinely is red-team/offensive:** don't try to word-smith it past the classifier. High-risk dual use (pentest, exploit dev, red-team automation) is policy-gated, not prompt-tunable — no system prompt reliably unblocks it. Use Opus 5 directly for known cyber/bio (same quality as the Claude fallbacks would give, at half the cost and no classifier dance), or your org's trusted-access path. Sol's "retry on lower-capability models" is the OpenAI-side equivalent.
