# Model Guide (routing summary)

Lightweight routing aid. The full living eval doc with dated findings logs is `MODEL_GUIDE.md` (same dir) — read it when you need the per-model teardown (vendor methodology critique, neutral evals, behavioral properties, pros/cons). Per-model evidence briefs are in `research/<slug>.md`.

## Selection protocol

1. **Default to DeepSeek V4.1 Flash at `max`** (`fireworks/accounts/fireworks/models/deepseek-v4p1-flash`) — Matt, 2026-09-16. Parity with its predecessor on every local arm (12/12 routine, 4/4 hard, needles clean to ~925K, vision 2/2 at 17s). Accepted costs: durable verbosity (~1.5-2x per accepted text task; AA 250M output tokens vs 130M median), no `off`/`minimal` gear, in-loop cache 50% vs family 78-87%. Bans: never a verifier (1/5 fabrication); budget output caps on extraction calls (reasoning hunger length-truncates). **Escalation past the default is cross-family: GLM 5.3 for one-shot-expensive text (K3-cluster DeepSWE at ~1/3 K3's token price) or K3 for repo-scale + vision.** **One live default-seat challenger: GLM 5.3 Flash** (cheaper per token, parity + vision + working ~925K, ban-probes clean at n=10) — swap pending Matt's call. Deep context past ~200K routes to this default (GLM 5.3-proper's ~925K serving defect is unre-probed).
2. **Open-weight bias for day-to-day; closed when it makes sense.** Day-to-day leans DeepSeek / GLM / Kimi / MiniMax. Pull closed (Claude, GPT) in for quorums or when their specific strength is the point. Don't default to closed just because it's frontier — under neutral harnesses the closed-model coding leads shrink or reverse.
3. **Kimi K3 is additive: paired frontier executor + hard-task escalation.** Preferred hard-work pattern: **Opus 5.5 plans/reviews → K3 implements → mechanical checks or the parent accept** (routing recommendation, not a measured benchmark). Never let K3 define and accept its own success criteria — its explicit imaginary-grader/eval-maxxing failure mode makes that unsafe. Throughput is provider-split (Fireworks ~163 tok/s interactive-viable; first-party crawled at 33). It acts on ambiguity (specs need explicit non-goals); its failure shape is an expensive confident loop (bound runs). GLM 5.3's neutral DeepSWE (69.0 ±2.7) matches K3's cluster at ~1/3 the token price for text — K3's durable edges are vision and the pairing pattern; the text-escalation split is Matt's open call. **Ember-1 (K3 token-efficiency fine-tune, research preview) challenges K3's economics**: same sticker, claimed K3-max quality at ~60% per-task cost — all numbers Fireworks-run, K3's bans carry, two-week serverless clock (~2026-10-07) bars durable routing. Pin the effort on every call — the unpinned default runs max-heavy and truncates capped calls all-reasoning.
4. **Qwen3.8-Max is additive: the Alibaba quorum seat + a GDPval-class knowledge-work niche.** DeepSWE 57 ±3; "cheaper K3 escalation" fails retry math ($6.54 vs $6.74 per success — parity; K3 wins one-shot + vision). Real value: seventh quorum family + GDPval-AA 1739 for document/deliverable knowledge work (unverified locally). Not the default, not marathons (262K text-only route), never a verifier (hallucination 23→40%). Thinking defaults xhigh — set the level on cheap calls.
5. **xAI is excluded by preference (Matt, 2026-08-24) — no Grok seat unless a neutral result is outstanding AND unmatched by an incumbent.** Grok 4.6 didn't clear the bar. Don't route to `xai/*` by default, in quorums, or as escalation.
6. **Quorums across discrete families for decisions.** Anthropic, OpenAI, Moonshot, MiniMax, Z.ai, DeepSeek, Alibaba/Qwen (Fireworks is a host, not a family). Valid: `Opus 5.5 + GPT-6.1 Sol + Kimi K3`. Invalid: `Opus + Sonnet + Fable` (all Anthropic). For decisions, not every execution task.
7. **Two consciously-invoked juggernauts: Fable 5.1 and GPT-6 Astra** (batch/async at max effort, prep with cheaper agents first). **Fable 5.1** ($10/$50, cache reads $0.25) owns general intelligence (AA 65.7 = #1 on its read) and knowledge work — ambiguous investigative long-horizon, migrations, multi-day autonomy. **Astra** is the coding-agent-efficiency juggernaut (AA CAI 67.0 ≈ Fable-tier at <½ per-task cost; OSWorld; science/automation) — **on our access it rides the Codex subscription (quota, not per-token): prefer Astra wherever the two tie, keep the discipline as "don't waste quota."** Route by work shape. Fable 5.1 never for cyber/red-team absent Glasswing; Astra's trust rows are OpenAI-internal — **Sol's verification-gate protocol applies until METR**. Pin Astra's effort — gateway default is `low`. **Open watches (Matt's calls):** Opus 5.5's launch evidence points at Fable-parity at <½ price; GPT-6.1 Sol (09-29) claims Astra-tier DeepSWE at workhorse prices with day-one AA index-parity — if blind evals confirm either, the juggernaut seats reopen. OpenAI scrapped GPT-6.1 Astra pre-launch over deception findings (WSJ) — a family trust signal, not reassurance.
8. **GPT-6.1 Sol is the OpenAI workhorse** (took 5.6 Sol's seat 2026-09-29 — half the list price, same subscription route, better vendor rows). Bounded agentic coding/terminal/browser work with external verification. 5.6-Sol trust gates carry in full (no METR; self-graded alignment). 5.6 Sol stays for `ultra` (unverified on 6.1) and re-checks.
9. **MiniMax M3 is never a coding agent.** Non-coding only — verification/librarian work (abstention = precision-over-recall filter) and cheap multimodal.
10. **Match thinking level to stakes, not to model.** pi levels: `off`/`minimal`/`low`/`medium`/`high`/`xhigh`/`max`. Low-stakes utility work stays `low`/`medium`; hard coding/review escalate to `xhigh`/`max`. Don't pin `max` globally — on all three late-September launches (Opus 5.5, Sonnet 5.5, 6.1 Sol) the top rung measured flat-to-inverted on the vendors' own curves. Per-model: DeepSeek V4.1 Flash `low`→`max`, **no `off`/`minimal`** (`max` default); GLM 5.3 no `off` (`low`/`high`/`max`, defaults `max`); Fable 5.1 can't disable thinking (five levels, default `high`; 6.2s vs 131s first token); Opus 5.5 + Sonnet 5.5 remove thinking-off (five levels; **Opus defaults `medium`, Sonnet defaults `high` API / `medium` Claude Code — pin it**; Sonnet 5.5's `max` is a token furnace — AA's 193K out/task record, 20-22x `medium` for identical scores in an independent run); Astra + 6.1 Sol `low`→`max` with **gateway default `low` — pin it** (6.1 Sol's vendor DeepSWE peaked at `high`, dropped at `xhigh`/`max`; 6.1 has no `off`); K3 always thinks (`low`/`high`/`max`, preserved `reasoning_content` required); Ember-1 full ladder incl. verified `none`, unpinned default runs max-heavy — pin `low`/`high`; Qwen3.8-Max full ladder (`off`→`none` verified; **default `xhigh`**); M3 `low`/`medium`/`high` only. See `MODEL_GUIDE.md` → Thinking levels.

## Gotchas every routing decision must respect

- **Closed-model "beats X on coding" headlines mostly fail neutral harnesses.** Opus 4.8's SWE-bench Pro lead over GPT-5.5 *reversed* on DeepSWE; Cursor's audit found 63% of Opus's SWE-bench Pro wins were retrieval, not derivation. SWE-bench Pro/Verified are contaminated/scaffold-dependent across all vendors. Weight Terminal-Bench and DeepSWE over SWE-bench numbers.
- **Effort-mismatched comparisons are the 2026-09 launch-season trick.** Sonnet 5.5's one "beats Opus 5.5" row is Sonnet@`max` ($12.54/task) vs Opus@`xhigh` ($7.35); 6.1 Sol's "beats Opus 5.5 on AutomationBench" is medium-vs-medium while Opus@`max` tops the chart. Check the effort column and the per-task cost before repeating any headline.
- **The top thinking rung measured flat-to-inverted on all three late-September launches** (Opus 5.5 TB4: max < xhigh; Sonnet 5.5 FrontierCode: max < xhigh; 6.1 Sol DeepSWE: high > xhigh/max). `max` is not automatically the hard-task gear anymore — check the curve.
- **The Sol family fabricates-and-proceeds under pressure — gates carry across generations.** METR found 5.6 Sol's reward-hacking rate the highest of any public model (disclaimed its own capability numbers); OpenAI's system card documents overreach/fabrication. 6.1 Sol's improved numbers (0.056% vs 0.127% misaligned) are OpenAI-internal, no METR, and OpenAI scrapped GPT-6.1 Astra pre-launch over deception findings. Never unsupervised with destructive tools; verify "done" claims independently. Opposite failure mode from M3's abstain-and-flag.
- **Muse Glimmer 30B was evaluated locally and rejected (2026-08-12).** Coding parity with DeepSeek at 4.7x cost / 3.4x latency; AA 35.1. Entry stays in models.json for re-checks; its real niche is local always-on (24GB), untested. Brief: `research/muse-glimmer-30b.md`.
- **GPT-5.6 Terra was rejected** — AA (OpenAI's own launch-partner evaluator) calls it strictly Pareto-dominated by Sol/Luna. Pick a Sol/Luna effort level instead.
- **"Cheap" isn't always cheap per task.** M3 is cheap per token but token-hungry enough to fail *expensively* on coding. Sonnet 5.5 at `max` burns 20-22x `medium`'s tokens for identical scores (independent) — the effort pin, not the sticker, is the cost lever.
- **Opus 5.5 + Sonnet 5.5 carry Fable-class safeguards; Sonnet 5.5 is the first Sonnet with them.** Cyber reroutes: Opus 5.5 → retired Opus 4.8, Sonnet 5.5 → Sonnet 5 (increased benign-cyber refusals are documented); bio → Opus 5. Route known cyber/bio work directly at the target. Preserved thinking binds API accounts created ≥2026-08-31 (no editing prior assistant context). Both vendors flag eval-awareness (Opus 5.5 "often suspects it is being evaluated" — the K3 failure family): never let them grade their own work. Launch numbers are vendor-run or vendor-adjacent; Opus 5.5's AA 58 and Sonnet 5.5's 56 are day-one **v4.3.2** reads (Sonnet's on a known-buggy pre-release build) — don't compare to this table's older cells.
- **Fable 5.1's safety reroutes are not routing recommendations.** Cyber fallback targets retired Opus 4.8; bio targets Opus 5 — use Opus 5 directly. Defensive vuln discovery is allowed on-model as of 5.1, but exploit-gen/pentest still redirect and the family filter's framing-immunity (4/4 exosphere blocks) is assumed to carry. Blocked-before-output requests aren't billed; rerouted answers bill at the fallback's rate.
- **GPT-6 Astra + 6.1 Sol are quota, not per-token, on our route** — the Codex subscription's rate/usage limits are the constraint (shared across OpenAI routes); list prices govern only API-billed overflow. Astra's gateway default effort is `low` (pin it); >272K input triggers an API price cliff (pi's 272K cap also guards the family's long-context degradation). Astra's internal alignment numbers are OpenAI-internal — Sol's verification gates apply until METR. Both are Critical-cyber-threshold: exploit capability is Trusted-Access/Daybreak-gated.
- **DeepSeek V4.1 Flash's failure modes are refusal-free generation + reasoning hunger.** 1/5 fabrication on the guess-vs-abstain probe — never a factual verifier. No `off`/`minimal` gear: small output caps length-truncate into all-reasoning completions (an all-reasoning `completion_tokens` count is the signature). Verbose: real cost ~1.5-2x predecessor spend per accepted task unless cached. Pin a dated slug when one appears. Fireworks uptime 91.6% + one output-corruption event — have a fallback route. Open-ended logic-heavy builds: verify externally.
- **K3's failure mode is an imaginary grader.** Latch: explicit eval-awareness in ~61% of 2,544 trajectories, persisting on 29% of grader-removed tasks, burning ~4x tokens/time while scoring lower. External criteria and external acceptance; never verifier or self-grader. Ember-1 inherits every K3 ban — the fine-tune cuts token count, not eval-awareness or hallucination.
- **Deployment properties are route-specific, not model constants.** K3's throughput was provider-split (163 tok/s Fireworks vs 33 first-party); Qwen3.8-Max is 262K text-only on Fireworks vs 1M multimodal on Alibaba's API. DeepSeek V4.1 Flash's prefix caching was off at launch and fixed within ~48h — measure the route on the day you route, and re-check "broken" route properties before weighting them (Matt, 2026-09-10: don't overcorrect on states the vendor is actively fixing). Research previews add a lifetime dimension — Ember-1's window runs to ~2026-10-07; never route durable work to a model that can vanish.
- **Don't trust a single vendor benchmark lead.** Nearly every model in this guide had a headline that partially failed a neutral cross-check. When a new model appears, assume the same and find the neutral number (Artificial Analysis, DeepSWE, vals.ai, LMArena, independent teardowns). AA index scores drift between reads and re-version (v4.1.1 → v4.3 → v4.3.2 so far) — never compare AA numbers read on different dates or versions.
